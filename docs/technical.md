# מסמך טכני: ציור לתלת-ממד

## ארכיטקטורה
- חזית (Frontend): דף סטטי אחד עם Three.js (גרסה 0.150.1). מציג את המודל, מאפשר סיבוב וזום, והורדה.
- שרת ביניים (Backend): שירות קטן שמקבל את הציור, שולח אותו למחולל המודלים, מחכה לתוצאה ומחזיר אותה לחזית. השרת מחזיק את מפתח ה-API, כדי שלא ייחשף בדפדפן.
- מחולל מודלים: Hunyuan3D, שרץ מקומית על GPU, או שירות חיצוני (Meshy) אם נבחר מסלול בתשלום.

## זרימת נתונים
1. החזית שולחת את הציור לשרת (POST).
2. השרת שומר את הקובץ ומעביר אותו למחולל.
3. השרת בודק את סטטוס העבודה כל כמה שניות.
4. כשהמודל מוכן, השרת מחזיר קישור לקובץ GLB.
5. החזית טוענת את הקובץ ב-GLTFLoader ומציגה אותו.

## מבנה הקבצים המוצע
- public/index.html: החזית (הקובץ model-viewer.html הקיים הוא הבסיס).
- server/app.py: שרת FastAPI עם נקודות קצה: העלאה, סטטוס, והורדה.
- server/adapters/: מתאם נפרד לכל מחולל (hunyuan.py, meshy.py), כך שאפשר להחליף בלי לשנות את השאר.
- data/: קבצי קלט ופלט זמניים. לא נכנסים לגיט.
- .env: מפתחות וכתובות (MESHY_API_KEY, HUNYUAN_URL). לא נכנס לגיט.

## נקודות קצה
- POST /api/convert: מקבל קובץ תמונה, מחזיר job_id.
- GET /api/jobs/{job_id}: מחזיר סטטוס (queued, running, done, failed) ואחוזים.
- GET /api/jobs/{job_id}/model: מחזיר את קובץ ה-GLB כשהעבודה הושלמה.

## אבטחה
- מפתחות API רק בצד השרת, בקובץ .env.
- הגבלת גודל קובץ (20MB) וסוגי קבצים (PNG, JPG, WEBP).
- מחיקת קבצים זמניים אחרי זמן קצוב.
- שום מידע אישי לא נשמר מעבר להיסטוריית ההמרות.

## בחירת מחולל
- Hunyuan3D: בחינם לשימוש, דורש GPU ו-Python. מתאים כשיש כרטיס NVIDIA מתאים.
- Meshy: שירות מסחרי עם API, דורש תוכנית בתשלום. מתאים כשאין GPU.
- המתאם משותף, כך שאפשר לעבור בין השניים בלי לשכתב את האפליקציה.

## מה לוודא לפני הבנייה
- דרישות הזיכרון של Hunyuan3D בעמוד הפרויקט הרשמי.
- נקודות הקצה והפורמט הנוכחיים של Meshy בתיעוד שלהם, אם נבחר בו.
